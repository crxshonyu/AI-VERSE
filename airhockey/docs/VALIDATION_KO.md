# 전달본 검증 범위

검증일: 2026-11-09. 버전: 1.1.0. 이 파일은 소프트웨어 검사 기록이며 하드웨어 성능 인증이 아닙니다.

## 수행한 검사

```bash
python3 -m unittest discover -s tests -v
ruff check .
ruff format --check .
python3 -m compileall -q airhockey tests
bash -n tools/install_pi.sh
```

Python unittest 총 **68개**:

| 영상 | 7 | 색상·원형도 검출, ROI·연관 게이트, 픽셀↔mm, 렌즈 좌표 일치 |

물리 테스트는 500개의 무작위 반사 사례를 별도 사건 기반 시뮬레이터와 비교합니다. 이동 시간은 0.1ms 간격의 독립적인 동역학 적분과 비교하며, 반대 방향 이동과 감속 후 재이동을 포함합니다. 통합 제어 테스트는 단순 예측 함수 호출에 그치지 않고, 정상 추적 이후 미검출·오래된 프레임으로 바뀌는 주 루프를 가상 카메라/모터로 실행합니다.

테이블 코너와 HSV 지정 CLI는 합성 PNG로 실제 실행했습니다. 또한 영상 생성 → OpenCV 검출 → 추적 → 반사 예측 → 모의 모터 → CSV와 확인 영상 저장을 연결하여 실행했습니다. 저장소의 `docs/simulation_preview.png`는 **합성 입력**입니다. 화면의 FPS·지연·검출률을 Raspberry Pi 4B나 실제 카메라의 성능으로 인용하면 안 됩니다. 실행 로그와 영상은 GitHub 소스에서 제외하고 재현 명령을 제공합니다.

GitHub 정리본은 별도의 새 Python 3.12 가상환경에 `.[headless,dev]`를 설치해 확인했습니다. 이 환경은 OpenCV 4.14.0과 NumPy 2.5.4를 사용했으며 Raspberry Pi용 카메라 패키지는 설치하지 않았습니다. 의도한 OpenCV 4.x 범위에서 검사했다는 의미이며 해당 PC의 처리 시간을 Pi 성능으로 환산하지 않습니다.

Python 3.11/3.13 GitHub Actions 워크플로는 추가했지만 원격 저장소에서 실행하지 않았습니다. 실제 CI 결과는 업로드한 저장소의 Actions에서 확인해야 합니다.

참고 펌웨어는 호스트 C++ API 스텁을 사용해 문법과 상태 전이를 검사했습니다. 이 검사는 실제 Arduino 툴체인 빌드, AccelStepper 구현을 포함한 시간 성능, 플래시/RAM 사용량, 모터 전류·토크·배선·제동을 검증하지 않습니다. 스텁 파일은 최종 제품 펌웨어가 아니므로 전달본에 포함하지 않습니다.

## 수행하지 못한 검사

- Raspberry Pi 4B의 실제 처리 FPS, 소비 메모리, 발열과 스로틀링.
- 실제 IMX708 Camera Module 3 Wide의 촬영 지연, 노출, 초점, 크롭과 렌즈 보정 잔차.
- Arduino 실제 툴체인 컴파일·업로드와 STEP 펄스 주기 측정.
- 실제 패들의 위치 오차, 스텝 유실, 가속·감속·한계 스위치·비상 정지.
- 실제 골대 센서 전압·극성·펄스 폭과 LED 배선.
- 실제 퍽의 벽 반발계수·마찰·회전과 종합 방어 성공률.

## 실물에서 권장하는 확인 순서

1. **정지 좌표:** 테이블 안의 알려진 위치 여러 곳에 퍽을 놓고 mm 오차를 확인합니다. 네 코너만 맞고 가장자리가 틀리면 렌즈 왜곡부터 점검합니다.
2. **직선 이동:** 모터 dry-run 상태에서 위치, 속도 부호, 카메라 프레임 나이와 처리 FPS를 확인합니다.
3. **반사 이동:** 한 번·여러 번 벽 반사를 확인하고 실제 방어선 교차 위치와 예상 위치의 오차를 측정합니다.
4. **모터 독립 점검:** 카메라 알고리즘과 분리하여 방향, 홈, mm 이동량, 속도/가속도, NC 스위치, 차단 회로를 점검합니다.
5. **느린 공격 통합:** 이동 공간을 확보한 뒤 천천히 퍽을 쳐 목표와 실제 위치를 비교합니다. 스텝 수 추정치만으로 위치 정확성을 판정하지 않습니다.
6. **센서/경기:** 한 번 통과, 계속 가림, 빠른 통과, 득점 후 재개, 150초 종료를 확인합니다.
7. **성능 측정:** 공격 속도·방향·반사 횟수별 방어 성공률, 예측 오차, 실제 패들 오차, 프레임/명령 지연을 기록합니다.

실제 구동 속도를 높이는 것은 검증 후 설정을 바꾸는 작업입니다. 이 전달본의 예제 치수·모터 속도는 측정값이나 보장값이 아닙니다.
